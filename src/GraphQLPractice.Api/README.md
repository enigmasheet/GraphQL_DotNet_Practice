# GraphQLPractice.Api

Hot Chocolate 16 GraphQL server over PostgreSQL, built with Entity Framework Core 10.

## Running

```powershell
dotnet run --project src\GraphQLPractice.Api
```

- `http://localhost:5100/graphql` — GraphQL endpoint + Nitro IDE (in a browser)
- `http://localhost:5100/graphql/ui` — the IDE on a dedicated path
- `http://localhost:5100/graphql/schema` — schema SDL

The database connection comes from `ConnectionStrings:Postgres` in
`appsettings.Development.json` (the shared `masterTest` instance on port `55432`). See
[../../docs/dev-setup.md](../../docs/dev-setup.md).

## Folder map

```
Program.cs                  # DI, CORS, subscriptions, EF, Nitro; runs migrations + seed in Development
Models/                     # Author, BlogPost, Comment, Tag, PostStatus
Data/
  AppDbContext.cs           # relationships + indexes
  AppDbContextFactory.cs    # design-time factory for `dotnet ef`
  SeedData.cs               # idempotent sample data
  Migrations/               # EF Core migrations
GraphQL/
  ModuleInfo.cs             # [Module("Types")] + [DataLoaderModule("DataLoaders")]
  Query.cs                  # [QueryType]
  Mutation.cs               # [MutationType] with [Error] types
  Subscription.cs           # [SubscriptionType] with [Subscribe]/[Topic]
  Types/                    # [ObjectType<T>] node resolvers (AuthorNode, BlogPostNode, CommentNode)
  DataLoaders/              # source-generated [DataLoader] batch + group loaders
  Errors/DomainExceptions.cs
Utilities/Slug.cs
```

## How it is wired

```csharp
builder.Services.AddDbContextFactory<AppDbContext>(o => o.UseNpgsql(connectionString));
builder.Services.AddDataLoaders();                 // generated by [DataLoaderModule]

builder.AddGraphQL()
    .AddTypes()                                    // generated by [Module]
    .AddFiltering()
    .AddSorting()
    .AddProjections()
    .AddInMemorySubscriptions()
    .AddMutationConventions(applyToAllMutations: true)
    .RegisterDbContextFactory<AppDbContext>();
```

- **Resolvers** take `AppDbContext` directly; `RegisterDbContextFactory` lets Hot Chocolate create
  the context per resolver so parallel query resolvers never share one.
- **DataLoaders** take `IDbContextFactory<AppDbContext>` and dispose their own context per batch.
- **Navigations** are `[GraphQLIgnore]`d; the schema exposes them only through DataLoader-backed node
  resolvers, which keeps the schema unambiguous and avoids N+1.

## Migrations

```powershell
dotnet ef migrations add <Name> --project src\GraphQLPractice.Api --output-dir Data\Migrations
dotnet ef database update --project src\GraphQLPractice.Api
```

`AppDbContextFactory` supplies the connection string at design time, so the CLI does not boot the web
app.

## Adding a feature

- **New query**: add a method to `Query.cs`. Use `[UsePaging]`, `[UseFiltering]`, `[UseSorting]`
  and/or `[UseProjection]` on `IQueryable<T>` returns.
- **New mutation**: add a method to `Mutation.cs`; with conventions enabled it gains an
  `...Input`/`...Payload` pair. Annotate with `[Error(typeof(MyException))]` to get typed errors.
- **New nested field**: add a `GetXAsync` method to the relevant `[ObjectType<T>]` class; inject the
  generated `I...DataLoader` interface.
- **New loader**: add a static `[DataLoader]` method to `GraphQL/DataLoaders/`; the interface and DI
  registration are generated on build.

See [../../docs/graphql-tour.md](../../docs/graphql-tour.md) for the concepts behind each piece.
